## The method (reusable — this is the important part)

The 14 local `docs/ecp/` engagements were all generated by **old code** (May–June).
The diagnostic reads *stored* output, so it grades whatever `review-state-*.json` is on
disk. To measure **current** code without a live browser:

```
# regenerate placement from stored acquisition+findings with CURRENT code:
python scripts/generate-editor.py --engagement docs/ecp/<id> --plugin-root . --overwrite-review-state
# re-grade it:
set PYTHONIOENCODING=utf-8   # (bash: export) cp1252 console guard
python scripts/diagnose_engagement.py --engagement docs/ecp/<id> --no-crops
```

`generate_editor_artifacts` re-runs `auto_map_markers_v2` from the stored `baton` +
`anchor-candidates` sidecars — **no live acquisition needed.** Sweeping all 14 + reading
each `_diagnosis/diagnosis.json` gives a corpus-wide, stage-attributed defect picture
(PLACEMENT / SPECIALIST / ACQUISITION). This offline regen→diagnose loop is how both
fixes below were found and verified. ⚠️ `docs/ecp/2026-06-08-8e46b1c8` is a **tracked
fixture** (worked-example for the diagnosis protocol + used by `test_diagnose_engagement.py`);
if a sweep dirties it, `git checkout -- docs/ecp/2026-06-08-8e46b1c8` to restore. The
other 13 engagements are gitignored.

### Discovery worth acting on later (re-anchoring)
`placement_repair.py` already does subject-text re-anchoring but **ignores the semantic
`anchor-candidates` role map** (`candidate_to_e_index`: `reviews-widget-1→e10`, etc.) — it
matches raw title tokens against element text and often scores 0.0. Teaching it to consult
the role map would help the ~41 "present-element + semantic-match" cases. **Caution:** naive
role matching has false friends (e.g. "Title Tag" SEO finding must NOT grab `product-title`);
build precision-first with false-friend guard tests. The threshold fix already handled the
*bulk* of the "reads approximate" problem, so this is lower priority now.
